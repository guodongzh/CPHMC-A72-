# SNTP对时功能设计文档

## 1. 概述

本文档描述了在 `CPEMC_2A` 项目中新增的 **SNTP (Simple Network Time Protocol)** 对时功能的设计与实现。该功能旨在为系统提供网络时间同步能力，作为现有 **IRIG-B 码对时** 的补充备份。

设计遵循 **“B码主用，SNTP备用”** 的原则，即仅在 IRIG-B 码信号丢失或失步时，才启用 SNTP 对时，以确保系统时间的可靠性和连续性。

## 2. 需求分析

1.  **功能需求**：
    *   支持 SNTP 客户端模式（Client Mode 3）。
    *   能够周期性向指定的 NTP 服务器发送时间同步请求。
    *   解析 NTP 服务器响应，更新系统本地 UTC 时间。
2.  **性能需求**：
    *   对时精度满足系统基本运行要求（毫秒级）。
    *   网络资源占用低，避免频繁发包。
3.  **优先级控制**：
    *   **IRIG-B 优先级最高**。
    *   当 IRIG-B 正常（同步或守时）时，SNTP 功能必须处于静默状态（不发包、不处理）。
    *   当 IRIG-B 失步（Lose）时，自动接管对时任务。
4.  **防抖动与临界区保护**：
    *   处理 SNTP 精度（秒级）与 CPU 时间（毫秒级）在整秒边界上的临界区问题。
    *   防止因网络延迟或计算误差导致的时间在整秒处反复跳变。

## 3. 软件架构

### 3.1 模块结构

SNTP 功能主要由以下几个部分组成：

1.  **SNTP 客户端核心 (`sntp_client.c/h`)**：
    *   负责构造 SNTP 请求报文。
    *   负责解析 SNTP 响应报文并提取时间戳。
    *   维护 SNTP 运行状态（轮询计数、有效性倒计时）。
    *   **新增**：大偏差防抖逻辑，处理临界区时间跳变。
2.  **网络协议栈适配 (`net_udp.c`)**：
    *   在 UDP 接收流程中拦截端口 **123** 的报文。
    *   通过回调机制将报文分发给 SNTP 客户端，避免报文丢失。
3.  **时间同步主逻辑 (`time_handle_main_prog.c`)**：
    *   集成 SNTP 的初始化与周期性调度。
    *   在硬中断中融合 B 码状态与 SNTP 状态，仲裁最终的时间源有效性。

## 4. 详细设计

### 4.1 接口设计 (`sntp_client.h`)

*   `void sntp_init(void)`: 初始化 SNTP 模块，注册 UDP 回调函数。
*   `void sntp_poll(void)`: 周期性轮询函数（建议 1 秒调用一次），负责倒计时和发送请求。
*   `bool sntp_is_valid(void)`: 查询当前 SNTP 对时是否处于有效期内。

### 4.2 关键流程

#### 4.2.1 发送请求流程 (`sntp_poll`)
1.  **前置检查**：读取 `sync_logic_inf.m_SyncState`。
2.  **决策**：
    *   若状态 **不为** `eSCHS_Lose`（即 B 码正常），重置发送计数器，**直接返回**。
    *   若状态 **为** `eSCHS_Lose`，执行步骤 3。
3.  **计数与发送**：
    *   计数器累加。
    *   若达到轮询间隔（默认 60 秒），构造 SNTP Mode 3 报文，向服务器（默认 192.168.10.20）发送 UDP 请求。

#### 4.2.2 接收处理流程 (`sntp_recv_callback`)
1.  **前置检查**：再次读取 `sync_logic_inf.m_SyncState`。若 B 码已恢复，丢弃报文。
2.  **报文解析**：
    *   定位 UDP 数据载荷。
    *   检查 Mode 字段是否为 Server (4)。
    *   提取 `Transmit Timestamp` (服务器发送时间)。
3.  **时间计算**：
    *   将 NTP 时间戳（1900年基准）转换为 Unix 时间戳（1970年基准）。
    *   公式：`Unix_Sec = NTP_Sec - 2208988800`。
4.  **防抖与临界区处理**：
    *   计算偏差 `diff = abs(SNTP时间 - CPU时间)`。
    *   **小偏差 (diff <= 2s)**：视为正常同步或临界区微调，**立即更新**系统时间，并清零防抖计数器。
    *   **大偏差 (diff > 2s)**：视为异常跳变或真实的时间不同步。
        *   计数器 `sntp_stable_counter` 加 1。
        *   若计数器达到 5 次（连续 5 次收到大偏差时间），确认为真实偏差，**强制更新**系统时间，并重置计数器。
5.  **状态更新**：
    *   更新全局时间结构 `Clk_Time_Edge.nUTC`（仅在允许更新时）。
    *   重置 `sntp_valid_countdown` 为 2 倍轮询周期（120秒），在此期间认为 SNTP 数据有效。

#### 4.2.3 状态仲裁流程 (`handle_synctime_Hard_Int_prog`)
在每秒的硬中断处理中：
1.  执行原有的 B 码状态机 `synctime_sync_statemachine()`。
2.  **补丁逻辑**：
    *   如果 B 码状态机判定为 `eSCHS_Lose` (失步)。
    *   **且** `sntp_is_valid()` 返回真。
    *   则强制将 `Clk_Time_Edge.nTimeState` 的 `SYNCLK_SYNC_SRC_OK_MASK` 位置 1。
    *   这确保了外部模块（如 FPGA、应用层）能感知到系统当前虽然 B 码没了，但时间源依然是有效的（由 SNTP 接管）。

## 5. 配置参数

| 参数名 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `SNTP_PORT` | 123 | 标准 NTP 端口 |
| `SNTP_POLL_INTERVAL_SEC` | 60 | 请求发送间隔（秒） |
| `sntp_server_ip` | 192.168.10.20 | NTP 服务器 IP 地址 |
| `sntp_valid_countdown` | 120 (动态) | 对时有效性保持时间（秒） |
| `SNTP_STABLE_THRESHOLD` | 5 | 大偏差防抖确认次数 |
| `SNTP_DIFF_THRESHOLD` | 2 | 时间偏差阈值（秒） |

## 6. 验证计划

1.  **B 码优先测试**：接入 B 码源，确认 SNTP 不发送任何报文。
2.  **切换测试**：拔掉 B 码源，等待进入失步状态，确认 SNTP 开始周期性发包，且系统时间能正常同步。
3.  **临界区测试**：模拟 CPU 时间与 SNTP 时间在整秒边界上微小差异（如 6.99s 和 7.01s），确认系统不会发生时间反复跳变或回退。
4.  **恢复测试**：恢复 B 码源，确认 SNTP 立即停止工作，系统无缝切回 B 码状态。
